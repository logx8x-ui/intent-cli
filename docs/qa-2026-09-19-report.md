### 1. Every browser tab can be selected

**Reproduction in source/tests:** `QuickSelection.isSelectable` required an HTTP(S) URL, and rows inherited its disabled state. PDF/internal/file/blank/loading targets could therefore be real browser tabs but unselectable. URL-derived browser scope also turned an internal-only blacklist into an app-wide block.

**Fix:** separate selection identity from page access. Exact browser/tab IDs carry live selection; URLs are optional replay metadata. Browser scopes remain tab-scoped with no web URL. Titles have readable fallbacks; preview limitations are explained without disabling selection. Geometry and focused-window metadata disambiguate equal window titles; an explicit window-list chooser handles remaining ambiguity without guessing a preview.

Browser session nonces prevent recycled IDs after restart from selecting different tabs. Chrome keeps its nonce across service-worker wakes using session storage; Firefox uses its background lifetime. The app pins selection identity, rejects changed targets, and stops a running selection on a changed browser session. The helper and guards carry and validate the same identity. Updated capabilities prevent an old bridge from silently pretending to support the new behavior.

Saved normal website intentions retain their existing URL-based replay behavior. A saved selection containing internal/non-web tabs explicitly requires reselection; transient tab IDs are not presented as durable resources.

**Evidence:** `Sources/IntentCoreSpec/TabSelectionSpec.swift`, native-host transport assertions, both browser background suites; see [tab ledger](qa-2026-09-19-tabs.md). Live hit testing/privileged-page enforcement remains blocked by QA permissions and the isolated browser connection.

### 2. Timer expiry notification

**Root cause:** expiry fed the dashboard's generic error state; the running panel was not an independent notification surface. A fixed civil-clock sleep also conflated elapsed duration with an absolute finish time.

**Fix:** an occurrence-scoped runtime policy uses continuous elapsed time for duration and civil time for End Time. Actual expiry emits one independent, dismissible “Time’s up” panel near the working display's center and stops restrictions. The panel cannot become key/main, auto-dismisses after eight seconds, and does not depend on running-control visibility. Expiry does not reactivate the app that was frontmost at session start. Cancelled/replaced occurrences cannot emit stale notices; locked/inactive login sessions suppress the visual notice without delaying restriction cleanup.

**Evidence:** deterministic forward/backward clock, sleep-advance, absolute deadline, duplicate expiry, cancellation/replacement and mixed deadline assertions in `SessionRuntimeSpecs.swift`. Four real one-minute Leisure sessions ended normally on prior candidate builds: one before the last shortcut patch and three after it; all four predate the later scroll-enforcement fix. The first displayed its countdown and “Time’s up” notice. The three later runs continued with controls hidden and returned to idle; their eight-second expiry notices were not reliably captured or checked because CUA could select/reopen the dashboard. Hidden-panel/background notice delivery is not a live pass. Focus-stealing, sleep/wake, lock, absolute-end-time and multiple-display behavior remain unverified live. Pause/resume is not a current runtime feature.

### 3. Shift-click and native groups

**Root cause:** selection only toggled individual IDs; browser metadata did not preserve native multi-selection.

**Fix:** ordinary clicks establish an anchor; Shift-click replaces the inclusive range in displayed order while preserving independent selections. Reverse, extending/shrinking, filtering/reorder, missing anchors and separate windows are handled by stable identity. Clearing marks also clears anchors. Native highlighted groups pass through metadata and double-backtick as a whole, and both allow/block execution preserve the complete group. An old guard must report the update requirement instead of silently applying only one tab. App-tile Shift-click keeps its separate always-allowed preset behavior.

**Evidence:** Core range/group cases, both browser group-policy suites, host metadata forwarding. Physical Shift-click/global-double-backtick remains blocked by QA permissions and the isolated browser connection.

### 4. Running overlay and gestures

**Root cause:** generic sessions created running controls; visibility was mixed with data refresh, and backtick used a toggle independent of the arrow.

**Fix:** only timer/end-time/checklist sessions automatically show controls. Per-occurrence visibility preserves hide across updates. Arrow and single backtick call the same collapse action; explicit restore remains available. Displayed absolute finish time and remaining duration are preserved. Controls have clearer typography, restrained glass, reduced-transparency support and persisted drag position. Selection UI takes priority; confirmed doubles cancel the single; synchronous routing and session-change cancellation prevent a pending single affecting a replacement run.

Further gesture regressions cover key-repeat, changed modifiers while held, paired key-up consumption and a delayed expiry callback. Intent-owned visible text editors and marked IME composition pass through; hidden editor state no longer suppresses global handling. Each Carbon shortcut registers independently, so one occupied shortcut does not prevent Safety Stop registration. This does not claim that bare backtick is available for ordinary typing in every external app. During an active session, a further single backtick retains the pre-existing restore-controls behavior; opening the selection overview is still refused until the current session ends.

**Evidence:** `SessionRuntimeSpecs.swift` and 100 controlled repeated sequences in `QuickGestureRegressionSpecs.swift`; optimized app compilation. Actual countdown/notice appearance and arrow-based hiding were observed in the isolated app. A CUA-generated backtick did not collapse the panel; app-targeted synthetic input can bypass the global event tap and QA Accessibility is absent. Physical gesture delivery is therefore unresolved, not a live pass. Dragging, layout/IME and display combinations remain unverified.

### Additional defects found during integrated review

- Late final review found that the native event tap omitted scroll-wheel events: a focused internal browser window whose tabs were all blocked could still receive scrolling. Wheel input now uses the existing focused-window cache to suppress scrolling over blocked content while preserving interactive Intent panels and system-transition handling. Five new regression cases and the final all-source automated suite passed; none of the recorded live runs validates this change.
- A browser window containing no allowed tabs had no valid tab to return to and could leave restricted content usable. Native enforcement now treats that exact focused window as blocked, including privileged pages without content scripts, while keeping every tab/window open. Native block-mode allowed-ID derivation now complements the selected blocked IDs.
- An Intent checklist/timer panel above restricted content could itself be blurred or have clicks intercepted. Explicitly registered interactive panel regions are excluded from native blur and input blocking; generic blur panels do not create an exemption. Region subtraction and keyboard-focus handling have deterministic regression coverage. Real enforcement interaction is still blocked by permissions.
- Chrome hover capture could move a tab and then restore an old tab over the user’s newer choice. The capture cleanup now validates the current window/active-tab state before restoring; the extension regression covers this race. Firefox preview capture does not activate tabs.
- The isolated app exposed an empty Settings scene while testing. Its scene identifier was corrected, and the packaged app was rebuilt before the second timer run.
