# Browser selection QA — 19 September 2026

Scope: attached issues 1 and 3, supported Chrome and Firefox integrations only. This pass edits source and deterministic test fixtures; it does not install, publish, access accounts, or inspect users' page content.

## Root causes and fixes

- **Unselectable internal/blank/local tabs:** `QuickSelection.isSelectable` required an HTTP(S) URL, the SwiftUI button was disabled for everything else, and session construction treated a website resource as mandatory. Selection now requires an actual browser/window/tab identity. Optional title/favicon/URL cannot disable a row; missing labels use “New tab.” The full row is hit-testable. Exact IDs reach both allow and block policy; web URLs are optional saved website metadata.
- **Internal-only blacklist could block the whole browser:** the policy inferred browser scope solely from website URLs. `selectionBrowserBundleIdentifiers` explicitly retains tab scope even without URLs; the model includes those browsers in readiness checks. Saved mixed/internal selections require selecting current tabs again rather than guessing ephemeral IDs. Saved web-only intentions retain established website replay behavior.
- **Missing range/group selection:** browser snapshots carried only the active bit and single-click toggled only one ID. Both guards and the host now carry `highlighted`, pinned/discarded/group metadata. `QuickSelection.selectTab` owns a per-window identity anchor and previous range; repeated Shift-click can grow/shrink while preserving independent selections. The native double-mark applies the entire highlighted group atomically. Old bridges are explicitly rejected with a nonmodal update notice; no partial group is advertised as success.
- **Equal browser window titles:** title-only matching made some real tab lists unreachable. Browser window ID, geometry and focus now flow through snapshots and disambiguate native preview/outline/access-control targets. Identical overlapping windows without a reliable match use an explicit browser-window list chooser instead of borrowing another preview's tabs. All rows remain identified by browser + tab ID. Browser window geometry is the frame-inclusive top/left/width/height exposed by the [browser window API](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/windows/Window).

- **Browser restart could reuse a numeric tab ID:** snapshots and exact-ID rules now carry a browser-lifetime nonce. Chrome keeps it in `storage.session` so ordinary service-worker wakes do not invalidate selection; Firefox binds it to its background lifetime. Selections pin that nonce, cannot silently replace it on refresh, and reject restarted browser sessions. Native/extension enforcement rejects mismatched or missing identity before applying exact IDs. Clearing targets also clears anchors and identity pins while preserving modifiers and mode.

The existing Shift-click app-preset handlers in `GraphEditors.swift` were inspected and left unchanged. Tab range handling is scoped to browser-tab row actions; it does not modify the global modifier-key handler or app-preset gesture.

## Limits and remaining validation

Selection does not promise content inspection. Internal/local/blank/sleeping tabs remain selectable, but their preview panel explains that content preview is unavailable. Native tab access control uses browser activation policy and macOS accessibility; public APIs do not expose a unique mapping for every identical overlapping native window, hence the explicit list chooser. Physical rendering, OS permissions, multi-display coordinates/scaling and actual restriction alignment still need the integrated live pass. Multiple simultaneously connected browser profiles are not covered by these fixtures. The guards and host fallback advertise version 0.2.12; this source version has not been installed or published by this subtask.
